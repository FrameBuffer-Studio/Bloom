# Холст

Холст (`canvas`) - это главный объект Bloom. В нём лежат черновик с пикселями, плитки для экрана, настройки, очередь задач и конвейер. Всё рисование идёт через него.

## Как устроен кадр

```text
 BeginFrame(цвет?)  →  рисуем  →  EndFrame()
       │                              │
       ├─ стадия "beginFrame"         ├─ стадия "endFrame"
       └─ заливка, если дан цвет      └─ Update() или UpdateAsync()
```

## Полезные поля холста

Их можно читать, но **не меняй их руками**: для этого есть функции.

| Поле | Что это |
|------|---------|
| `canvas.res_x` | Ширина холста в пикселях |
| `canvas.res_y` | Высота холста в пикселях |
| `canvas.tile_size` | Размер одной плитки |
| `canvas.size_x`, `canvas.size_y` | Сколько плиток по ширине и по высоте |
| `canvas.tiles` | Плитки (номер → `{x, y, w, h, editable, buffer, image}`) |
| `canvas.async` | Планировщик задач этого холста ([глава 10](10-scheduler.md)) |
| `canvas.pipeline` | Конвейер стадий ([глава 11](11-pipeline.md)) |

## Создание

### `Bloom.Create(resolution, parent?, reference?, options?)`

**Что делает:** создаёт новый холст. Если передать `parent` и `reference`, картинка появится на экране.

**Аргументы:**

| Имя | Тип | Обязательный? | Что это |
|-----|-----|---------------|---------|
| `resolution` | `Vector2` | да | Размер холста в пикселях, например `Vector2.new(320, 240)`. Дробная часть отбрасывается |
| `parent` | `Instance?` | нет | Куда положить картинки: `Frame`, `ScreenGui`, `SurfaceGui` и так далее |
| `reference` | `ImageLabel?` | нет | Образец. Bloom копирует его для каждой плитки |
| `options` | `Options?` | нет | Дополнительные настройки (смотри таблицу ниже) |

**Настройки `options`:**

| Поле | По умолчанию | Что делает |
|------|--------------|------------|
| `tile_size` | `1024` | Размер плитки. Число округляется вниз и зажимается в пределы от 1 до 1024 |
| `async_budget` | `0.002` | Сколько секунд за один шаг может работать планировщик. Меньше `0.0001` не бывает |
| `scheduler_options` | `{}` | Настройки планировщика ([глава 10](10-scheduler.md)) |
| `auto_clip` | `true` | Включить `ClipsDescendants` у `parent`, чтобы картинка не вылезала за рамку |
| `clear_color` | `0` | Цвет для `Clear()` без аргумента. `0` - полностью прозрачный |

**Возвращает:** холст (`Bloom`).

**Пример:**

```lua
local canvas = Bloom.Create(Vector2.new(320, 240), frame, template, {
	tile_size = 512,
	clear_color = Color4.New32Bit(20, 20, 30),
})
```

**Все исходы:**

- ✅ **Есть `parent` и `reference`.** Для каждой плитки создаётся копия `reference`. Ей задаются размер в пикселях (`UDim2.fromOffset`), позиция, `ImageContent` и `Visible = true`, а потом она кладётся в `parent`. Один пиксель холста равен одному пикселю экрана.
- 🌑 **Нет `reference`.** Холст рисует «в невидимку»: всё работает, но на экране ничего не появляется. Так удобно готовить картинки заранее или считать что-то по пикселям.
- 👻 **Есть `reference`, но нет `parent`.** Копии создаются, но никуда не кладутся, поэтому их не видно.
- ✂️ **`parent` - это `GuiObject`** (например, `Frame`), и `auto_clip` не выключен. Тогда у `parent` включается `ClipsDescendants = true`. У `ScreenGui` такого свойства нет, и Bloom его не трогает.
- 🧩 **Холст больше `tile_size`.** Он режется на плитки. Плитки в последнем столбике и последней строчке могут быть меньше остальных.
- 🎨 **Начальный цвет.** Новый холст полностью прозрачный (все пиксели `0`), даже если указан `clear_color`. Чтобы залить его этим цветом, вызови `canvas:Clear()`.
- 🧼 **Грязные плитки.** Сразу после создания все плитки считаются «грязными», поэтому первый `Update()` отправит их на экран.
- 🚫 **Размер меньше 1** (например, `Vector2.new(0, 100)`) - ошибка `Bloom.Create expects a positive resolution`.
- 🚫 **EditableImage выключен в настройках игры** - ошибка с подсказкой про `Allow Mesh / Image APIs` ([глава 2](02-setup.md)).
- 🧠 **Закончилась память.** Ошибка `Bloom: EditableImage memory budget is exhausted (ШxВ tile)`. Все плитки, которые Bloom успел создать до ошибки, он сам удалит, поэтому память не утечёт.

### `Bloom.FromEditableImage(editable_image, holder)`

**Что делает:** превращает уже существующую `EditableImage` в холст. Пиксели из картинки копируются в черновик, так что можно рисовать поверх них.

**Аргументы:**

| Имя | Тип | Что это |
|-----|-----|---------|
| `editable_image` | `EditableImage` | Твоя картинка, не больше 1024 × 1024 |
| `holder` | `ImageLabel` | `ImageLabel`, который уже показывает эту картинку |

**Возвращает:** холст.

```lua
local editable = AssetService:CreateEditableImage({ Size = Vector2.new(128, 128) })
imageLabel.ImageContent = Content.fromObject(editable)

local canvas = Bloom.FromEditableImage(editable, imageLabel)
canvas:DrawLine(1, 1, 128, 128, Color4.New32Bit(255, 0, 0))
canvas:Update()
```

**Все исходы:**

- ✅ Холст получает одну плитку - твою картинку. Её текущие пиксели становятся черновиком.
- 🔒 Картинка и `ImageLabel` **остаются твоими**: `canvas:Destroy()` их не удалит.
- 🧼 Плитка **не** считается грязной сразу: на экране и так твоя картинка. Обновится она после первого рисования.
- 🚫 Картинка больше 1024 по любой стороне - ошибка `Bloom.FromEditableImage supports images up to 1024x1024`.
- 🚫 Размер картинки 0 - ошибка `Bloom.FromEditableImage expects a positive resolution`.
- 🚫 Потом нельзя вызвать `Resize` - будет ошибка (смотри ниже).
- ℹ️ Эта функция не проверяет настройки игры. Раз у тебя уже есть `EditableImage`, значит они включены.

## Кадр

### `canvas:BeginFrame(clear_color?)`

**Что делает:** начинает новый кадр. Если передать цвет, весь холст сначала заливается им.

| Имя | Тип | Что это |
|-----|-----|---------|
| `clear_color` | `number?` | Цвет заливки. Если не передать, холст не очищается |

**Все исходы:**

- ✅ Есть цвет - вызывается `Clear(цвет)`, потом запускается стадия `beginFrame`.
- ✅ Нет цвета - старая картинка остаётся, запускается только стадия `beginFrame`.
- 💤 Холст уже удалён - ничего не происходит.

> [!NOTE]
> `BeginFrame()` **без** аргумента не заливает холст даже цветом из `SetClearColor`. Если нужна очистка цветом по умолчанию, вызови `canvas:Clear()`.

### `canvas:EndFrame(use_async?)`

**Что делает:** заканчивает кадр и показывает его на экране.

| Имя | Тип | Что это |
|-----|-----|---------|
| `use_async` | `boolean?` | `true` - отправлять по кусочку через `UpdateAsync()`. Иначе всё отправляется сразу через `Update()` |

**Все исходы:**

- ✅ Запускается стадия `endFrame`, потом `Update()` или `UpdateAsync()`.
- 💤 Холст удалён - ничего не происходит.

## Показ на экране

### `canvas:Update()`

**Что делает:** сразу отправляет все грязные плитки на экран.

**Все исходы:**

- ✅ Запускаются стадии `beforeUpload` → загрузка каждой грязной плитки → `afterUpload`. Плитки становятся чистыми.
- ✋ Если какие-то плитки ждали отправки через `UpdateAsync`, это ожидание отменяется: `Update` отправит их сам.
- ⚠️ Плитку не удалось отправить (Roblox выдал ошибку) - появится предупреждение `[Bloom] Failed to upload tile N: ...`. Плитка останется грязной и попробует отправиться в следующий раз. Остальные плитки отправятся как обычно.
- 💤 Нет грязных плиток - стадии всё равно запустятся, но загрузок не будет.
- 💤 Холст удалён - ничего не происходит.
- 🐢 Roblox обновляет на экране **одну** `EditableImage` за кадр. Если грязных плиток 4, картинка может догонять 4 кадра. Это правило Roblox, а не ошибка Bloom.

### `canvas:UpdateAsync(budget?)`

**Что делает:** ставит грязные плитки в очередь планировщика. Каждая плитка - отдельная задача. Работа размазывается по времени, и игра не подвисает.

| Имя | Тип | Что это |
|-----|-----|---------|
| `budget` | `number?` | Сколько секунд планировщик может работать за шаг. Запоминается навсегда (минимум `0.0001`) |

**Все исходы:**

- ✅ Запускается `beforeUpload`, каждая грязная плитка встаёт в очередь, и планировщик стартует.
- 📦 После каждой загруженной плитки запускается стадия `tileUploaded`. После последней - `afterUpload`.
- 🔁 Плитка уже стоит в очереди - второй раз она не ставится. Пиксели берутся в момент отправки, поэтому уйдут самые свежие.
- 💤 Грязных плиток нет - сразу запускается `afterUpload`, и планировщик не стартует.
- ✋ `Update()`, `Resize()` или `Destroy()` отменяют эту очередь.
- ⚠️ Планировщик общий: вместе с плитками он выполнит и твои задачи из `canvas:Submit`.
- 💤 Холст удалён - ничего не происходит.

## Очистка и цвет фона

### `canvas:Clear(color?)`

**Что делает:** заливает **весь** холст одним цветом.

| Имя | Тип | Что это |
|-----|-----|---------|
| `color` | `number?` | Цвет. Если не передать, берётся цвет из `SetClearColor` (или `clear_color` из настроек) |

**Все исходы:**

- ✅ Весь холст закрашен, все плитки грязные.
- 🖼️ Окошко рисования (`SetViewport`) **не** действует: очищается всё.
- ⚡ Цвет `0` заливается особенно быстро.
- 💤 Холст удалён - ничего не происходит.

### `canvas:SetClearColor(color)`

**Что делает:** запоминает цвет, которым `Clear()` будет заливать холст без аргумента.

```lua
canvas:SetClearColor(Color4.New32Bit(0, 0, 0))
canvas:Clear()
```

**Все исходы:** ✅ цвет запомнен. Сам холст при этом не меняется.

## Окошко рисования (viewport)

Viewport - это рамочка-трафарет. Всё, что рисуется за её пределами, обрезается.

```text
 ┌────────────── холст ──────────────┐
 │                                   │
 │     ┌── viewport ──┐              │
 │     │  здесь можно │              │
 │     │   рисовать   │              │
 │     └──────────────┘              │
 └───────────────────────────────────┘
```

### `canvas:SetViewport(x, y, width, height)`

| Имя | Тип | Что это |
|-----|-----|---------|
| `x`, `y` | `number` | Левый верхний угол окошка (с 1) |
| `width`, `height` | `number` | Ширина и высота окошка |

```lua
canvas:SetViewport(10, 10, 100, 50)
canvas:DrawRectangle(1, 1, 500, 500, RED)
canvas:ResetViewport()
```

**Все исходы:**

- ✅ Окошко задано. Числа округляются вниз.
- ✂️ Окошко вылезает за холст - оно обрезается по краям холста.
- 🕳️ Ширина или высота 0 или меньше, либо окошко целиком за холстом - окошко получается пустым, и **ничего не рисуется**, пока не вызовешь `ResetViewport`.
- ℹ️ На окошко смотрят: `DrawPixel`, все линии, прямоугольники, треугольники, текстуры, текст и шейдеры.
- ℹ️ На окошко **не** смотрят: `Clear`, `ReadPixel`, `DrawPixelUnsafe`, `ReadPixelUnsafe` и прямая запись в `GetBuffer()`.

### `canvas:ResetViewport()`

**Что делает:** возвращает окошко на весь холст.

**Все исходы:** ✅ рисовать снова можно везде.

## Состояние и прямой доступ

### `canvas:GetState()`

**Что делает:** возвращает **живую** табличку состояния `{ clear_color, viewport = { x, y, w, h } }`.

**Все исходы:** ✅ табличка - это не копия, а оригинал. Если поменять её поля, поменяется сам холст. Лучше используй `SetViewport` и `SetClearColor`.

### `canvas:GetBuffer()`

**Что делает:** отдаёт сам черновик - `buffer`, в котором лежат все пиксели.

**Как найти пиксель в буфере:** `смещение = ((y - 1) * canvas.res_x + (x - 1)) * 4`.

```lua
local pixels = canvas:GetBuffer()
local offset = ((5 - 1) * canvas.res_x + (3 - 1)) * 4
buffer.writeu32(pixels, offset, Color4.New32Bit(255, 0, 0))
canvas:MarkDirty(3, 5, 3, 5)
canvas:Update()
```

**Все исходы:**

- ✅ Можно читать и писать напрямую. Это самый быстрый способ.
- ⚠️ Bloom **не знает**, что ты что-то поменял. Обязательно вызови `MarkDirty`, иначе изменения не появятся на экране.
- ⚠️ После `Resize()` создаётся **новый** буфер. Старая ссылка больше не связана с холстом - возьми буфер заново.
- 🚫 Смещение за пределами буфера - ошибка Luau `buffer access out of bounds`.

### `canvas:MarkDirty(x0, y0, x1, y1)`

**Что делает:** говорит Bloom: «в этом прямоугольнике я что-то поменял, отправь его на экран».

**Все исходы:**

- ✅ Все плитки, которые задевает прямоугольник, становятся грязными. Углы можно передавать в любом порядке.
- ✂️ Прямоугольник обрезается по холсту.
- 💤 Прямоугольник целиком за холстом - ничего не происходит.

## Размер и удаление

### `canvas:Resize(resolution)`

**Что делает:** меняет размер холста.

```lua
canvas:Resize(Vector2.new(640, 480))
```

**Все исходы:**

- ✅ Старые плитки удаляются, создаются новые. Черновик становится новым и полностью прозрачным. Окошко сбрасывается на весь холст. Все плитки грязные.
- 🧹 Ожидающие отправки через `UpdateAsync` отменяются.
- 🗑️ **Старая картинка пропадает.** Если она нужна, перерисуй её.
- 🚫 Холст создан через `FromEditableImage` - ошибка `Resize is not supported for contexts created with FromEditableImage`.
- 🚫 Размер меньше 1 - ошибка `Bloom.Resize expects a positive resolution`.
- 🧠 Не хватило памяти на новые плитки - ошибка про memory budget. Холст остаётся без плиток. Попробуй размер поменьше или удали холст.
- 💤 Холст удалён - ничего не происходит.

### `canvas:Destroy()`

**Что делает:** выключает холст навсегда и освобождает память.

**Все исходы:**

- ✅ Планировщик останавливается, все задачи отменяются.
- ✅ Свои `EditableImage` и копии `ImageLabel` удаляются (если холст сделан через `Create`).
- 🔒 Если холст сделан через `FromEditableImage`, твои картинка и `ImageLabel` остаются.
- 🔁 Повторный вызов ничего не делает.
- 💤 После удаления `Update`, `Clear`, `BeginFrame`, `EndFrame`, `Resize`, `DrawTexture`, `DrawText` и `ApplyShader` ничего не делают. Линии и фигуры ещё пишут в старый черновик, но на экран это больше не попадёт. Просто не используй удалённый холст.

> [!TIP]
> Удаляй холст, когда он больше не нужен, например при выходе из меню. `EditableImage` занимает много памяти, особенно на телефонах.
