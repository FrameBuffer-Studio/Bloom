# Статистика и скорость

## Счётчики

### `canvas:GetStats()`

**Что делает:** отдаёт **копию** всех счётчиков холста и его планировщика.

```lua
local stats = canvas:GetStats()
print(("Отправлено %d плиток, %.1f КБ"):format(stats.uploaded_tiles, stats.uploaded_bytes / 1024))
```

| Поле | Что считает |
|------|-------------|
| `update_calls` | Сколько раз закончилось обновление экрана |
| `last_update_seconds` | Сколько длился последний `Update()` |
| `uploaded_tiles` | Сколько плиток отправлено на экран |
| `uploaded_bytes` | Сколько байт отправлено |
| `upload_seconds` | Сколько всего времени ушло на отправку |
| `shader_pixels` | Сколько пикселей прошло через шейдеры |
| `texture_pixels` | Сколько пикселей нарисовано текстурами и текстом |
| `text_glyphs` | Сколько букв нарисовано |
| `scheduler_pending` | Задач в очереди |
| `scheduler_active` | Задач выполняется сейчас |
| `scheduler_completed` | Задач выполнено |
| `scheduler_failed` | Задач упало |
| `scheduler_cancelled` | Задач отменено |
| `scheduler_last_step_seconds` | Длина последнего шага планировщика |
| `scheduler_max_step_seconds` | Самый долгий шаг планировщика |

### `canvas:ResetStats()`

**Что делает:** обнуляет счётчики холста.

**Все исходы:** ✅ поля `update_calls` … `text_glyphs` становятся 0. ⚠️ Счётчики планировщика (`scheduler_*`) **не** обнуляются: они живут в `canvas.async`.

## Правила быстрой игры

| Правило | Почему |
|---------|--------|
| Делай холст маленьким | Каждый пиксель - работа процессора и память. 512 × 512 в 4 раза дешевле, чем 1024 × 1024 |
| Перерисовывай только то, что поменялось | Bloom отправляет на экран только грязные плитки |
| Используй `tile_size` поменьше для больших холстов, где меняются маленькие кусочки | Тогда грязными становятся маленькие плитки, а не огромные |
| Не делай слишком маленькие плитки | Каждая плитка - отдельная `EditableImage` и отдельная загрузка |
| Рисуй прямоугольниками и текстурами, а не тысячами `DrawPixel` | Один вызов, который заливает всю строчку, быстрее тысячи вызовов |
| Для непрозрачных текстур ставь `blend = false` | Смешивание цветов стоит дорого |
| Применяй шейдеры к маленьким кусочкам | Шейдер вызывает функцию для **каждого** пикселя |
| Создавай шрифты, текстуры и шейдеры один раз | Создание дорогое, а рисование дешёвое |
| Используй `UpdateAsync` при больших обновлениях | Работа размажется по кадрам |
| Удаляй ненужные холсты через `Destroy()` | На телефонах мало памяти для `EditableImage` |

## Ограничения Roblox

- Одна `EditableImage` - не больше 1024 × 1024. Bloom сам режет холст на плитки.
- На экране за один кадр обновляется только **одна** `EditableImage`. Если плиток много, картинка обновляется по очереди.
- У телефонов строгий лимит памяти для `EditableImage`. Если он кончится, `Create` выдаст ошибку про memory budget.
- В опубликованной игре нужно включить **Allow Mesh / Image APIs** ([глава 2](02-setup.md)).

## Как найти тормоза

1. Открой **MicroProfiler** (Ctrl + F6) или **Script Profiler** в Studio.
2. Сравни `canvas:GetStats()` до и после подозрительного места.
3. Если растёт `shader_pixels` - уменьши шейдер. Если растёт `uploaded_bytes` - перерисовываешь лишнее.
