# Цвета

## Из чего сделан цвет

Любой цвет на экране смешивается из трёх лучиков: **красного** (R), **зелёного** (G) и **синего** (B). Есть ещё четвёртое число - **прозрачность** (A, «альфа»). Оно говорит, насколько цвет плотный.

Каждое число - от **0** до **255**:

| Число | Для R, G, B | Для A (альфа) |
|-------|-------------|---------------|
| 0 | этого лучика нет | цвет невидимый |
| 128 | половина | полупрозрачный |
| 255 | лучик на полную | цвет совсем плотный |

| Цвет | R | G | B |
|------|---|---|---|
| Чёрный | 0 | 0 | 0 |
| Белый | 255 | 255 | 255 |
| Красный | 255 | 0 | 0 |
| Зелёный | 0 | 255 | 0 |
| Синий | 0 | 0 | 255 |
| Жёлтый | 255 | 255 | 0 |
| Фиолетовый | 128 | 0 | 255 |

## Цвет как одно число

Bloom хранит цвет как **одно** большое число (32 бита). В нём 4 ячейки по 8 бит, и красный лежит в самой младшей:

```text
 0x AA BB GG RR
    │  │  │  └── красный  (биты 0–7)
    │  │  └───── зелёный  (биты 8–15)
    │  └──────── синий    (биты 16–23)
    └─────────── альфа    (биты 24–31)
```

Например, непрозрачный красный - это `0xFF0000FF`. В таком же порядке байты лежат в `EditableImage:ReadPixelsBuffer()`, поэтому Bloom ничего не переставляет и работает быстро.

> [!TIP]
> Не нужно запоминать порядок байтов. Просто используй `Color4.New32Bit(r, g, b, a)`.

## Где взять Color4

### `Bloom.GetColor4()`

**Что делает:** отдаёт модуль с функциями для цветов.

```lua
local Color4 = Bloom.GetColor4()
```

**Все исходы:** ✅ всегда возвращает один и тот же модуль.

## Функции для чисел-цветов

### `Color4.New32Bit(R, G, B, A?)`

**Что делает:** собирает цвет-число из четырёх частей.

| Имя | Тип | Что это |
|-----|-----|---------|
| `R`, `G`, `B` | `number` | Красный, зелёный, синий (0–255) |
| `A` | `number?` | Прозрачность (0–255). Если не передать, будет **255** (совсем плотный) |

```lua
local orange = Color4.New32Bit(255, 140, 0)
local glass = Color4.New32Bit(200, 230, 255, 100)
```

**Все исходы:**

- ✅ Возвращает число-цвет.
- ✂️ Число больше 255 или меньше 0 «обрезается по маске»: у него берутся только младшие 8 бит. Например, 256 станет 0, а 300 станет 44. Чтобы было «не больше 255», сначала используй `math.clamp`.
- ✂️ Дробное число округляется вниз, потому что так работает `bit32`.

### `Color4.Unpack(color)`

**Что делает:** разбирает цвет-число обратно на 4 части.

```lua
local r, g, b, a = Color4.Unpack(orange)
```

**Возвращает:** `r, g, b, a` - четыре числа от 0 до 255.

**Все исходы:** ✅ всегда четыре числа.

### `Color4.SetR(color, value)`, `Color4.SetG(color, value)`, `Color4.SetB(color, value)`, `Color4.SetA(color, value)`

**Что делает:** меняет одну часть цвета и возвращает **новое** число. Старое число не меняется.

```lua
local halfOrange = Color4.SetA(orange, 128)
```

**Все исходы:**

- ✅ Возвращает новый цвет.
- ✂️ Значение `value` вне диапазона 0–255 обрезается по маске, как в `New32Bit`: от него остаются только младшие 8 бит. Передавай целое число от 0 до 255.

### `Color4.BlendOver(destination, source)`

**Что делает:** кладёт цвет `source` **поверх** цвета `destination`, как цветное стёклышко на рисунок. Учитывает прозрачность обоих цветов.

```lua
local result = Color4.BlendOver(
	Color4.New32Bit(0, 0, 255),
	Color4.New32Bit(255, 0, 0, 128)
)
```

**Все исходы:**

- ✅ `source` совсем плотный (A = 255) - результат равен `source`.
- ✅ `source` совсем невидимый (A = 0) - результат равен `destination`.
- ✅ В остальных случаях цвета смешиваются. Чем плотнее `source`, тем больше его в результате.
- ✅ Оба цвета невидимые - результат `0`.

> [!NOTE]
> Bloom использует «прямую» прозрачность (straight alpha), а не «предумноженную» (premultiplied). Цвет хранится как есть, а альфа лежит рядом отдельно.

### `Color4.Zero`

Это просто число `0` - полностью прозрачный чёрный.

## Цвет-объект

Иногда удобнее работать с объектом, у которого есть поля `R`, `G`, `B` и `A`.

### `Color4.New(R, G, B, A?)`

**Что делает:** создаёт объект-цвет.

```lua
local sky = Color4.New(135, 206, 235)
print(sky.R, sky.G, sky.B, sky.A)
```

**Все исходы:**

- ✅ Числа **округляются** до ближайшего целого и **зажимаются** в пределы 0–255. Так, 300 станет 255, а −5 станет 0. Объект безопаснее, чем `New32Bit`.
- ✅ `A` по умолчанию 255.

### `color:To32Bit()`

**Что делает:** превращает объект в число-цвет для функций рисования.

```lua
canvas:Clear(sky:To32Bit())
```

### `Color4.From32Bit(color)`

**Что делает:** превращает число-цвет обратно в объект.

### `Color4.FromColor3(color, alpha?)`

**Что делает:** превращает обычный `Color3` из Roblox (части от 0 до 1) в объект `Color4`.

```lua
local c = Color4.FromColor3(Color3.fromRGB(255, 100, 0))
```

**Все исходы:** ✅ части умножаются на 255 и округляются. `alpha` по умолчанию 255.

### `color:Lerp(other, t)`

**Что делает:** находит цвет «между» двумя цветами. `t = 0` - первый цвет, `t = 1` - второй, `t = 0.5` - ровно посередине.

```lua
local red = Color4.New(255, 0, 0)
local blue = Color4.New(0, 0, 255)

for x = 1, 100 do
	local mix = red:Lerp(blue, (x - 1) / 99)
	canvas:DrawVerticalLine(x, 1, 20, mix:To32Bit())
end
```

**Все исходы:**

- ✅ Возвращает новый объект-цвет.
- ✂️ `t` меньше 0 считается за 0, больше 1 - за 1.

## Важно: рисование заменяет цвет

> [!WARNING]
> `DrawPixel`, `DrawLine`, `DrawHorizontalLine`, `DrawVerticalLine`, `DrawRectangle` и `DrawTriangle` **заменяют** пиксель целиком, вместе с прозрачностью. Полупрозрачный прямоугольник не смешается с фоном, а сделает дырку.
>
> Смешивают цвета только `DrawLineAA`, `DrawTexture` (по умолчанию) и `DrawText`. Для остального используй `Color4.BlendOver` сам.
