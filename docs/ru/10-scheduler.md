# Планировщик задач

Представь, что у тебя много домашних дел. Если делать всё сразу, ты устанешь и ничего не успеешь. Лучше делать понемногу: немного сейчас, немного потом. Самые важные дела - первыми.

**Планировщик** (`Async`) так и работает. Он делает задачи маленькими порциями и следит, чтобы каждая порция влезала в **бюджет** - немного миллисекунд. Так игра не подвисает.

```text
 очередь:  [важно!] [обычное] [обычное] [фоновое] ...
              │
   шаг Step() - работаем ≤ budget секунд
              ▼
           готово ✓
```

У каждого холста есть свой планировщик: `canvas.async`. Можно сделать и отдельный: `Bloom.Async.New()`.

## Приоритеты

| Приоритет | Что значит |
|-----------|------------|
| `0` | Самое срочное |
| `1` | Обычное (по умолчанию) |
| `2` | Не срочное |
| `3` | Фоновое, когда больше нечего делать |

Внутри одного приоритета задачи идут **по очереди**: кто раньше пришёл, тот раньше выполнится.

**Старение.** Задача, которая долго ждёт, становится важнее: каждые `aging_interval` секунд (по умолчанию 0.25) она поднимается на один уровень. Так фоновые задачи тоже когда-нибудь выполнятся.

**Срок (deadline).** Если у задачи вышел срок, она прыгает впереди всех обычных приоритетов.

## Создание

### `Bloom.Async.New(budget?, options?)`

**Что делает:** создаёт новый планировщик.

| Имя | По умолчанию | Что это |
|-----|--------------|---------|
| `budget` | `0.002` | Секунд на один шаг (минимум `0.0001`) |
| `options.poll_interval` | `0.001` | Пауза между шагами в `Start()`, в секундах |
| `options.aging_interval` | `0.25` | Через сколько секунд ожидания задача становится важнее |
| `options.max_tasks_per_step` | `256` | Сколько задач максимум за один шаг (минимум 1) |

```lua
local scheduler = Bloom.Async.New(0.001, { max_tasks_per_step = 64 })
```

Для холста эти настройки задаются в `Bloom.Create` через `async_budget` и `scheduler_options`.

## Добавить задачу

### `scheduler:Submit(callback, ...)`

**Что делает:** ставит задачу в очередь с обычным приоритетом. Все аргументы после функции передаются ей.

```lua
local job = canvas.async:Submit(function(name, count)
	print(name, count)
end, "привет", 3)
```

**Возвращает:** задачу (`Task`).

**Все исходы:**

- ✅ Задача стоит в очереди со статусом `"pending"`.
- ⏸️ Сама она **не запустится**. Нужно вызвать `scheduler:Start()` или `scheduler:Step()`.
- 🚫 `callback` не функция - ошибка `Async.Submit expects a function`.

### `scheduler:SubmitWithOptions(callback, options, ...)`

**Что делает:** то же самое, но с приоритетом и/или сроком.

| Поле `options` | Что это |
|----------------|---------|
| `priority` | От 0 до 3. Число округляется вниз и зажимается в эти пределы |
| `deadline` | Срок - **абсолютное** время `os.clock()`, а не «через сколько секунд» |

```lua
canvas.async:SubmitWithOptions(function()
	print("срочно!")
end, { priority = 0, deadline = os.clock() + 0.05 })
```

### `canvas:Submit(callback, ...)` и `canvas:SubmitWithOptions(callback, options, ...)`

Это короткие версии `canvas.async:Submit` и `canvas.async:SubmitWithOptions`.

## Запуск

### `scheduler:Start()`

**Что делает:** запускает фоновый цикл. Он сам вызывает `Step()`, ждёт `poll_interval` и повторяет.

**Все исходы:**

- ✅ Задачи начинают выполняться сами.
- 🔁 Цикл уже запущен - ничего не происходит.
- ℹ️ Цикл сделан на `task.spawn` и `task.wait` и **не** подключается к `RenderStepped` или `Heartbeat`.
- ℹ️ Когда задачи кончаются, цикл продолжает тихо крутиться и ждать новых. Остановить его можно через `Stop()`.

### `scheduler:Stop()`

**Что делает:** останавливает фоновый цикл. Задачи **остаются** в очереди, и их можно продолжить через `Start()` или `Step()`.

### `scheduler:Step(budget?)`

**Что делает:** выполняет задачи **один раз, прямо сейчас**, пока не кончится бюджет.

**Возвращает:** `number` - сколько задач было запущено или продолжено.

```lua
RunService.Heartbeat:Connect(function()
	canvas.async:Step(0.001)
end)
```

**Все исходы:**

- ✅ Задачи выполняются по приоритету.
- ⏱️ Бюджет проверяется **между** задачами. Первая задача выполняется всегда, даже если она долгая.
- 🛑 За один шаг выполняется не больше `max_tasks_per_step` задач.
- 0️⃣ Очередь пустая - возвращает `0`.

## Длинные задачи и паузы

Планировщик **не может** остановить задачу посреди работы. Если задача долгая, раздели её на кусочки и между ними говори «я подожду».

### `Bloom.Async.Yield()`

**Что делает:** ставит текущую задачу на паузу и отпускает другие. Задача возвращается в очередь и потом продолжит с этого же места.

```lua
canvas.async:Submit(function()
	for row = 1, canvas.res_y do
		canvas:DrawHorizontalLine(1, row, canvas.res_x, Color4.New32Bit(row % 256, 0, 0))
		if row % 32 == 0 then
			Bloom.Async.Yield()
		end
	end
	canvas:Update()
end)
canvas.async:Start()
```

**Все исходы:**

- ✅ Внутри задачи - пауза, и задача получает статус `"yielded"`.
- 🚫 Вне задачи - ошибка `Async.Yield must be called from inside a scheduler task`.

> [!CAUTION]
> Внутри задачи **нельзя** использовать `task.wait()`, `wait()` и другие ожидания Roblox (например, `:WaitForChild()` или `HttpService:GetAsync()`). Задача сразу станет `"failed"` с ошибкой `Task yielded outside Async.Yield(); ...`. Для пауз используй только `Bloom.Async.Yield()`.

## Задача (Task)

| Поле | Что это |
|------|---------|
| `job.state` | Статус (смотри таблицу ниже) |
| `job.priority` | Приоритет |
| `job.submitted_at`, `job.started_at`, `job.finished_at` | Время по `os.clock()` |
| `job.deadline` | Срок |
| `job.error` | Текст ошибки, если задача упала |

| Статус | Что значит |
|--------|------------|
| `"pending"` | Ждёт в очереди |
| `"running"` | Выполняется прямо сейчас |
| `"yielded"` | На паузе после `Yield()`, ждёт продолжения |
| `"completed"` | Выполнена ✓ |
| `"cancelled"` | Отменена ✗ |
| `"failed"` | Упала с ошибкой 💥 |

### `job:Cancel()`

**Что делает:** отменяет задачу.

**Все исходы:**

- ✅ Задача ждёт (`pending`) или на паузе (`yielded`) - она станет `"cancelled"` и не выполнится.
- 💤 Задача уже выполнена, упала или отменена - ничего не происходит.
- ⚠️ Задача выполняется прямо сейчас - отменить её нельзя.

### `job:IsCancelled()` и `job:IsFinished()`

**Что делает:** быстро отвечает, отменена ли задача и закончилась ли она.

- `IsCancelled()` → `true`, если статус `"cancelled"`.
- `IsFinished()` → `true`, если статус `"completed"`, `"cancelled"` или `"failed"`.

## Ошибки в задачах

Если задача выдала ошибку:

- ✅ Планировщик **не ломается** и выполняет остальные задачи.
- 📝 У задачи `state = "failed"`, а в `job.error` лежит текст ошибки.
- ⚠️ В консоли появляется `[Bloom.Async] Task failed: ...`.

## Уборка и счётчики

### `scheduler:Clear()`

**Что делает:** отменяет **все** задачи в очереди.

**Все исходы:** ✅ все ждущие и стоящие на паузе задачи становятся `"cancelled"`. ⚠️ Задача, которая выполняется прямо сейчас, остановится только на своём следующем `Yield()`.

### `scheduler:PendingCount()`

**Возвращает:** сколько задач ждёт или стоит на паузе.

### `scheduler:GetStats()`

**Возвращает:** копию счётчиков.

| Поле | Что это |
|------|---------|
| `pending` | Ждут |
| `active` | Выполняются сейчас |
| `completed` | Выполнено всего |
| `failed` | Упало всего |
| `cancelled` | Отменено всего |
| `last_step_seconds` | Сколько длился последний шаг |
| `max_step_seconds` | Самый долгий шаг |

### `scheduler:Destroy()`

**Что делает:** `Stop()` и `Clear()` вместе. `canvas:Destroy()` вызывает его сам.

> [!NOTE]
> Планировщик **не** делает работу параллельной на нескольких ядрах. Он только честно делит время. Не рисуй на одном холсте из разных `Actor` одновременно.
